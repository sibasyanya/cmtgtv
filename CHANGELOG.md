# Changelog

Все важные изменения проекта Cybermasters TG TV (CMTGTV) фиксируются в этом файле.

## [1.0.21] - 2026-09-21

### Исправлено (Ошибки компиляции Kotlin в GitHub Actions)
- **Исправление сигнатуры и вызовов метода `send()` в `TdLibManager.kt`:**
  - Параметр `callback` в методе `send(query, callback)` сделан опциональным со значением по умолчанию `null` (`callback: ((TdApi.Object) -> Unit)? = null`), что предотвращает ошибку Kotlin `Null cannot be a value of a non-null type` и `No value passed for parameter 'callback'`.
  - Исправлены вызовы `send(TdApi.RemoveProxy(id))` и `send(TdApi.DisableProxy())`.
  - Устранен вызов `currentClient.send(TdApi.Close(), null)` в `resetSession()`, заменен на `currentClient.send(TdApi.Close()) {}`.
- **Исправление импорта в `QrAuthScreen.kt`:**
  - Добавлен отсутствовавший импорт `com.tgmedia.tv.ui.proxy.TgDivider` для разделителей и рамок в интерфейсе авторизации Android TV.

## [1.0.20] - 2026-09-21

### Изменено и оптимизировано (Смена наименования на Cybermasters TG TV / CMTGTV и устранение OOM Exit Code 9 в GitHub Actions)
- **Смена названия приложения:**
  - Полное наименование изменено на **Cybermasters TG TV**.
  - Сокращенное наименование — **CMTGTV**.
  - Названия обновлены во всех манифестах, ресурсах Android (`strings.xml`, `AndroidManifest.xml`), заголовках интерфейса, `package.json`, `metadata.json` и в именах генерируемых APK-файлов (`cmtgtv-vX.Y.Z.apk`).
- **Устранение сбоя сборки в GitHub Actions (Exit code 9 / OOM Killer):**
  - Ошибка exit code 9 в Linux вызывается системным OOM Killer при исчерпании лимита оперативной памяти на раннере GitHub Actions из-за параллельных форков Gradle и Kotlin-компилятора при сборке тяжеловесного 5MB Java-класса TDLib `TdApi.java` (140,000 строк).
  - В `android/gradle.properties` и `.github/workflows/release.yml` настроены безопасные параметры памяти:
    - `org.gradle.parallel=false`
    - `org.gradle.workers.max=2` (флаг `--max-workers=2`)
    - `org.gradle.jvmargs=-Xmx3072m -XX:+UseParallelGC`
    - `kotlin.daemon.jvmargs=-Xmx1536m -XX:+UseParallelGC`
  - Добавлены явные зависимости `androidx.compose.material3:material3` и `androidx.compose.material:material-icons-extended` в `build.gradle.kts` для гарантированной компиляции диалогов и компонентов без ошибок типов.

### Добавлено и изменено (Официальные настройки прокси Telegram, скрейпинг mtproto.ru, вход только по номеру)
- **Полное удаление авторизации по QR-коду:**
  - Убраны все вызовы и состояния генерации QR-кодов, которые вызывали зависания и ошибки `[400] Another authorization query`.
  - Приложение теперь работает со 100% фокусом на авторизацию по номеру телефона в международном формате с поддержкой экранной клавиатуры для пульта ДУ телевизора, кода подтверждения и пароля двухфакторной аутентификации (2FA).
- **Настройки прокси в точности как в официальном клиенте Telegram (по предоставленным скриншотам):**
  - Реализованы 3 режима: «Отключить прокси», «Использовать системные настройки прокси», «Использовать собственный прокси».
  - Поддержка опции «Через IPv6 (если возможно)».
  - Настройка «Автопереключение прокси» с выбором времени ожидания (5 с, 10 с, 15 с, 30 с, 60 с).
  - Поддержка всех 4 типов прокси: MTPROTO, SOCKS5, HTTP, WEB с адресом сокета (хост, порт) и учётными данными (секретный ключ или логин/пароль).
  - Проверка доступности (пинг в мс) каждого прокси в реальном времени со статусами: «подключён», «доступен (X мс)», «недоступен», «проверка...».
  - Меню управления: «Проверить», «Изменить», «Удалить», «Удалить все», «Добавить из буфера обмена».
- **Автоматический парсинг и проверка рабочих MTProto прокси с `https://mtproto.ru/main.php`:**
  - Создан парсер `MtprotoScraper`, который в реальном времени извлекает актуальные прокси-серверы из таблицы mtproto.ru.
  - Каждый найденный прокси валидируется перед добавлением через прямое открытие сетевого сокета и замер задержки отклика (RTT).
  - Добавлена кнопка «С mtproto.ru» прямо в окно настроек прокси для загрузки рабочих прокси в один клик с пульта.

## [1.0.17] - 2026-09-20

### Исправлено (Зависание авторизации, ошибка [400] Another query, обход блокировок в РФ)
- **Устранение ошибки `[400] Another authorization query has started`:**
  - В `TdLibManager.kt` добавлен флаг `isQrRequestInProgress` и строгий контроль параллельных запросов. При нажатии «Обновить QR», если предыдущий запрос ожидает ответа сокета, повторный вызов блокируется, предотвращая отказ TDLib по коду 400.
  - Добавлена функция безопасного перезапуска сетевой сессии `restartSession()` для сброса подвисших сокетов без перезапуска приложения.
- **Встроенная поддержка Proxy (MTProto / SOCKS5) для обхода блокировок в РФ:**
  - На территории РФ прямое подключение к серверам Telegram (DC 1-5) часто блокируется или замедляется провайдерами (ТСПУ), из-за чего запрос сокета зависает в статусе `Connecting`.
  - Реализован класс `ProxySettings` и методы `applyProxy`/`disableProxy` через нативные функции `TdApi.AddProxy` / `TdApi.DisableProxy`.
  - Добавлены готовые пресеты MTProto и локального SOCKS5 с сохранением в `SharedPreferences` и автоматическим применением при старте.
- **Альтернативный вход по номеру телефона:**
  - Реализован полнофункциональный режим входа по номеру телефона (`SetAuthenticationPhoneNumber`, `CheckAuthenticationCode`, `CheckAuthenticationPassword` для 2FA) с виртуальной цифровой клавиатурой для пульта ДУ.
- **Улучшенный интерфейс Android TV (10-Foot UI):**
  - Раздельные статусы соединения сети (`ConnectionState`) и процесса авторизации.
  - Наглядные подсказки при задержке ответа серверов Telegram.

## [1.0.13] - 2026-09-19

### Исправлено (Устранение ошибки AUTH_TOKEN_INVALID1 при сканировании QR)
- **Устранена причина ошибки `AUTH_TOKEN_INVALID1`:**
  - В предыдущей сборке из-за отсутствия скомпилированной нативной библиотеки `libtdjni.so` приложение работало в аварийном режиме с демонстрационным статичным токеном (`DemoSafeModeTvPreviewToken`), который серверы Telegram закономерно отвергали при сканировании официальным клиентом Telegram на телефоне.

  - Синхронизирован официальный Java-мост `Client.java` (пакет `org.drinkless.tdlib`) с нативным C++ бинарником.
  - Теперь ядро TDLib связывается напрямую с серверами Telegram и получает подлинный, криптографически подписанный токен сессии (`tg://login?token=...`), который успешно авторизует реальный аккаунт при сканировании смартфоном.
- **Индикация статуса TDLib на ТВ (`QrAuthScreen`):**
  - Добавлен наглядный индикатор состояния («QR-код активен (готов к сканированию)» / «Инициализация ядра Telegram...»).

  - Оформлен `android/gradle/libs.versions.toml` (Gradle Version Catalog) с версиями Kotlin 2.0+, Jetpack Compose for TV (`androidx.tv:tv-material:1.1.0`, `tv-foundation:1.0.0-alpha11`), Media3 ExoPlayer 1.11.0, Coil, ZXing и Coroutines.
  - Настроен `android/app/build.gradle.kts` с Target SDK 35, Min SDK 26, поддержкой ABI `arm64-v8a` и `armeabi-v7a`, и подключением директории `jniLibs` для `libtdjni.so`.
- **Модуль 2 (Слой TDLib Manager):**
  - Создана реактивная обертка `TdLibManager` над синглтоном `org.drinkless.tdlib.Client`.
  - Потокобезопасный `StateFlow<TdApi.AuthorizationState>` для отслеживания сессии.
  - Метод `sendTdlibParameters()` с передачей `api_id`, `api_hash`, путей к SQLite БД и кэшу видеофайлов.
  - Интеграция `TdApi.RequestQrCodeAuthentication` со стримингом `tg://login?token=...` через `StateFlow<String?>`.
  - Модели и функции `TdApi.java` и JNI-мост `Client.java`.
